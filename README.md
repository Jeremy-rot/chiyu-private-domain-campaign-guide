## 你可能天天遇到这个场景

老板一句「下个月搞个会员日，你出个方案」，然后就没了。

你打开电脑，翻出上一年那套，改改日期、换个赠品、调下调性，交上去。心里清楚：这东西大概率又是一次「发券、发朋友圈、等着核销」的重复劳动，做完不知道效果从哪来，也说不清下一次该改什么。

问题从来不是不会写方案，而是缺三样东西：

- **策略**：这个活动到底为解决什么问题而存在，指标怎么拆，为什么是这几个数
- **节奏**：预热多久、爆发几天、收尾怎么逼单，谁在第几天做什么
- **数据**：怎么算才有说服力，哪些指标必须咬合，什么信号出现就该踩刹车

这三样，是绝大部分品牌和运营人最薄弱的三个环节，也是这个技能存在的唯一理由。

## 它交付什么

不是一段「建议」，是五份能直接进会、直接下发、直接执行的表：

| # | 交付物 | 里面是什么 |
|---|---|---|
| 1 | **月度内容排期表** | 4321 栏目矩阵，一个月每天发什么、发几条、什么栏目，提前排掉 |
| 2 | **活动方案** | 6 要素 + 3 段节奏，目标—动作—指标三层咬合，缺一层即判反模式 |
| 3 | **玩法机制** | K 系数自检（K<1 不放量）+ 防刷四道闸，算得出来才算过 |
| 4 | **物料清单 BOM** | 每件物料谁做、什么规格、什么时候必须到位 |
| 5 | **门店执行与 KOS 协同排期** | 总部排什么、门店做什么、督导查什么，责任到人 |

第 5 项是它和市面上绝大多数方案的真正分水岭。

线上代运营公司写到「活动方案」那页就结束了。但连锁品牌的死穴恰恰在后面那一段：**总部很热，门店很冷，方案写得再漂亮，门店不动就等于零。** 所以这里会往下排到人——总部、门店、KOS 三层各自的动作和时间点，店长、店员、达人各自发什么、每周最多发几条。

纯线上品牌会自动降级成账号矩阵版本，不会硬塞门店排期。

## 它怎么想问题（这部分才是它值钱的地方）

随便一个 AI 都能给你编一份方案。区别在于**它会不会自我否定**。

举三个它内置的硬规则：

**K 系数必须算出来。** 裂变玩法写完必须给出 `K = 人均邀请数 × 邀请转化率` 的具体数值，`K < 1` 一律不准放量。市面上大量方案只写「邀请 3 人得 50 元券」，从来不算 K 值、不设熔断线——所以活动一放量就被薅穿。

**防刷四道闸必须齐全。** 同一设备/IP 限制、奖励延迟 24 小时兑现、风控阈值 + 人工抽检、仅新用户计入邀请数。少一道，方案就是漏洞。

**三层必须咬合。** 互动率 → 复购券核销率 → 业绩，写成一个闭环。目标只写「提升活跃」而不对应到业绩的，直接判反模式重写。

它还会主动拦住这些常见事故：赠品成本击穿毛利、活动价与日常价格体系打架、社群发券导致沉默用户被反复打扰而删好友、门店执行走样到无法归因……

**会拦你，才叫专业。**

## 快速开始

### 1. 安装

它就是一个 `SKILL.md` 目录，遵循 [agentskills.io](https://agentskills.io) 开放标准，**不绑定任何平台**。`name` 和 `description` 两个必需字段齐备，平台专有字段会被其他客户端自动忽略，不影响加载。

```bash
# 一条命令装到你所用客户端（把最后那段路径换成下面表格里对应的位置）
git clone https://github.com/Jeremy-rot/chiyu-private-domain-campaign-guide.git \
  ~/.workbuddy/skills/chiyu-private-domain-campaign-guide
```

**注意**：clone 的目标文件夹名必须保持 `chiyu-private-domain-campaign-guide`（与 `SKILL.md` 里的 `name` 一致），不要解压散放在 skills 根目录下，否则客户端扫不到。

#### 各客户端放置位置（官方文档路径）

| 客户端 | 位置 | 装法 |
|---|---|---|
| **WorkBuddy** | `~/.workbuddy/skills/` | 放目录 |
| **Claude Code** | `~/.claude/skills/`（全局）<br>`.claude/skills/`（项目） | 放目录 |
| **Codex CLI** | `~/.agents/skills/`（个人）<br>`.agents/skills/`（项目） | 放目录，或用 `$skill-installer` 从仓库装 |
| **Cursor** | `~/.cursor/skills/` 或 `~/.agents/skills/`<br>（同时兼容读 `.claude/skills`、`.codex/skills`） | 放目录 |
| **Trae** | 全局 `~/.trae-cn/skills`（国内版）/ `~/.trae/skills`（国际版）<br>项目 `.trae/skills/` | **设置 → 技能与命令 → 创建 → 上传 .zip** |
| **千问工作台 QwenWork** | `~/.qwenworkcn/skills/` | **对话里发仓库链接让它装，或左侧「扩展 → 技能」上传** |

| **GitHub Copilot** | `~/.copilot/skills/`、`.github/skills/` 或 `.agents/skills/` | 放目录 |

> **覆盖最广的目录是 `.agents/skills/`** —— Cursor、Codex、Copilot、Gemini CLI、Qwen Code、Trae、Cline、Amp、Warp 等都会读它。没有哪一个目录能覆盖全部客户端，这是各家的实现差异，不是本技能的限制。

装好后告诉 AI「用 chiyu-private-domain-campaign-guide 帮我做活动方案」，或者直接描述需求让它自己匹配。

### 2. 安装依赖（可选，只有要导出 Excel 才需要）

```bash
pip install openpyxl
```

### 3. 调用

在对话里直接说：

```
帮我给龙歌自助小火锅做一份 10 月会员日活动方案，西安，60 家门店，客单价 59 元
```

它会先问你 8 个问题，不会一上来就瞎写：

1. 行业与品类
2. 品牌名 + 门店数量
3. 城市与区域分布
4. 客单价带
5. 本次活动的核心目标
6. 现有私域规模与状态
7. 历史活动做过什么、结果如何
8. 预算与可调用的资源

答完，约 10 分钟出五件套。不满意可以继续说「按这个方向重排节奏」「门店执行再细一层」，它会改。

## 什么情况下别用它

- 你要的是**对外比稿用的视觉稿**——它给的是能执行的表，不是 PPT 美化
- 你**还没有任何私域用户沉淀**，连 500 好友都没有——先去解决拉新，活动方案救不了空池子
- 你想让它替你**拍板**——它负责把选项摊开、把风险标出来、把账算清楚，但决定的人还是你

## 方法论底座

- 《持续变现私域底层架构》：造 IP → 做链接 → 搞促活 → 做分层 → 拉复购（本技能落在「搞促活」这一环）

这两套框架是我给连锁品牌做私域咨询时反复验证过的，不是从教科书上抄的。
